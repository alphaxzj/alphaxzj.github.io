# MeshTalk 加密去中心化群聊

MeshTalk 是纯前端点对点群聊应用。页面可放在任意静态托管服务上；聊天消息通过 WebRTC DataChannel 在浏览器节点之间直接传输，静态服务器只负责分发文件。

## 功能

- 多节点网状群聊：一个页面同时维护多条 WebRTC 连接。
- 手动邀请码 / 回复码完成节点发现，无需自建信令服务器。
- 批量房间邀请包：一次生成多人名额，成员共用同一个邀请包加入。
- 邀请链接：主机可把邀请包编码为 `#invite=` 链接，成员打开后自动填充。
- 应用层端到端加密：设置至少 8 位房间密钥后，使用 PBKDF2 派生 AES-256-GCM 密钥加密所有应用消息。
- 一跳 gossip 转发：消息携带唯一 ID，在直连节点间转发一次，重复消息自动丢弃。
- 邀请配对记录：多条邀请码按目标节点保存并显示状态。
- 生成邀请码 / 回复码后自动尝试复制。
- TURN 配置支持，可用于严格 NAT、企业网络或跨运营商连接。
- 成员列表、平均延迟、心跳保活、连接失败诊断、全部断开。
- 本地历史记录：按房间密钥指纹隔离保存，可加载最近 200 条或清空当前房间。
- 成员目录同步：节点间交换已知成员，自动为可直连成员生成新邀请码。
- 消息频率限制：发送端限制突发消息；接收端检测异常高频并断开恶意连接。
- 图片与文件传输：通过 DataChannel 加密分片发送，最大 12MB；图片显示预览，文件提供下载。
- 文件传输可靠性：分片 ACK 确认、缺失重传、DataChannel 缓冲区背压控制。
- 内置 emoji 面板，可快速插入表情。
- 响应式界面，适配桌面与移动端。

## 本地运行

推荐通过 `localhost` 或 HTTPS 运行，以便使用剪贴板、压缩和 Web Crypto API：

```powershell
cd decentralized-chat
python -m http.server 8000
```

访问：

```text
http://localhost:8000
```

跨设备使用时，请部署到 HTTPS 静态托管地址，或通过内网穿透工具暴露本地服务。

## 安全模型

- 所有 WebRTC 数据通道已有 DTLS 传输加密。
- 设置相同房间密钥后，聊天、成员身份、心跳等应用消息会额外进行 AES-GCM 加密。
- 房间密钥不会写入 localStorage，也不会进入邀请码。
- 本地记录以房间密钥指纹作为隔离标识。记录仍保存在浏览器 IndexedDB 中，请只在可信设备启用历史功能；如需最高隐私，使用后点击“清空当前房间”。
- PBKDF2 使用固定应用盐值与 210000 次迭代；固定盐值适合这个轻量房间口令方案，但不会替代独立高熵密钥。
- 请通过可信渠道把房间密钥告诉成员；若需要更强身份保证，应另行校验成员身份指纹。
- 文件在发送前读取为二进制分片，每片随应用消息一起 AES-GCM 加密。请勿接收来自不可信成员的未知文件。

## 批量房间模式（推荐）

1. 主机设置「邀请名额」，点击「生成批量邀请包」。
2. 把同一个邀请包发给所有要加入的成员。
3. 第一个成员把「名额编号」设为 1，第二个设为 2；粘贴邀请包后生成各自的回复包并发回主机。
4. 主机把每个成员发来的完整回复包逐行粘贴，点击「批量连接成员」。
5. 状态显示直连节点数量后即可加密群聊。

## 单人邀请模式

1. A、B、C 打开同一页面，设置名称，并输入相同的房间密钥。
2. A 点击两次「创建邀请码」，分别发给 B 和 C。
3. B 粘贴 A 的第一条邀请码生成回复码并发回 A。
4. C 粘贴 A 的第二条邀请码生成回复码并发回 A。
5. A 逐条粘贴回复码并点击「连接对方」。
6. 状态显示两个直连节点、三人群聊后即可通信。

B 与 C 之间也可以继续交换邀请码，建立全连接网状网络；这样即使 A 离开，B/C 之间仍有路径。

## TURN 配置

如果双方无法直连，在「TURN 服务器」填入可信服务地址，例如：

```text
turn:your-turn.example.com:3478
```

填写 TURN 用户名和密码后点击「保存网络设置」。凭据只会保存在当前浏览器本机。
