# MeshTalk 去中心化聊天平台

MeshTalk 是一个纯前端、点对点的浏览器聊天应用。消息通过 WebRTC DataChannel 直接在两台设备之间传输；本项目可部署到任意静态托管服务，但服务端只分发页面，不保存聊天记录。

## 功能

- WebRTC DataChannel 点对点通信，默认启用 DTLS 传输加密。
- 多节点网状群聊：一个页面可同时维护多条加密连接。
- 手动邀请码 / 回复码完成节点发现，无需自建信令服务器。
- 消息携带唯一 ID，收到后在其他直连节点间转发一次，并自动丢弃重复消息。
- Gzip + Base64 压缩邀请内容，降低复制成本。
- 成员列表、待处理连接、心跳保活、连接状态提示、主动断开。
- 响应式界面，适配桌面与移动端。
- 消息仅保存在当前页面 DOM 中；刷新即清空。

## 本地运行

推荐通过 localhost 或 HTTPS 运行，以便使用剪贴板和压缩 API：

`powershell
cd decentralized-chat
python -m http.server 8000
`

在同一台机器的两个浏览器窗口访问：

`	ext
http://localhost:8000
`

跨设备使用时，请把目录部署到你自己的静态托管地址，或通过内网穿透工具暴露本地服务。

## 群聊流程

以三人群聊为例：

1. A、B、C 都打开同一个应用，并设置不同显示名称。
2. A 点击「创建邀请码」，把第一条邀请码发给 B；再点击一次生成第二条邀请码发给 C。
3. B 粘贴 A 发来的邀请码，点击「生成回复码」，把回复码发回 A。
4. C 也粘贴 A 发来的对应邀请码，生成回复码后发回 A。
5. A 逐条粘贴回复码并点击「连接对方」。
6. 连接建立后，A、B、C 可直接聊天；消息会在 MeshTalk 节点之间转发。

更稳定的方式是让任意成员之间也单独交换邀请码，形成全连接网状网络；即使某一条连接断开，其他路径仍可继续转发。

## 隐私边界

- STUN 只用于发现网络候选地址，不传输消息内容。
- 邀请码包含临时 SDP 与 ICE 候选，不应长期公开。
- 如需隐藏 IP 或穿越严格 NAT，可在 pp.js 顶部的 ICE_SERVERS 中添加你信任的 TURN 服务。
- 当前实现是一跳 gossip：收到消息会转发给除来源外的所有直连节点，并通过消息 ID 防止重复循环。它不是匿名网络，也不能替代端到端密码学审计。
